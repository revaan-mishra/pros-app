# PROS implementation handoff

Use the existing app at `outputs/pros-app`. The canonical product plan is [EXPERIENCE-OVERHAUL-PLAN.md](EXPERIENCE-OVERHAUL-PLAN.md). The enhanced folder is reference material, not a replacement implementation.

Paste this to begin:

```text
Implement the PROS experience overhaul in docs/EXPERIENCE-OVERHAUL-PLAN.md.

Start with Phase 0, then complete Phase 1: the new Today opening, explicit pinned project, complete Atelier expedition, one focus place, existing shared activity capture, an output-derived keepsake, and one compact save result. Keep every visible control functional. This is implementation work, not another planning exercise.

Read the plan once, then inspect only relevant current source. Preserve records, stable IDs, deterministic XP, offline command transactions, undo, account namespaces, and exports. Reuse the current stack and authored assets that fit the chosen style. Use isolated sample data for the new experience; never fabricate real progress. Fix relevant saving/draft problems before routing new interactions through them.

No manual app testing at this stage. Use TypeScript/build and targeted automated checks. Report actual results and unverified checks honestly. Do not publish until Firebase accounts/private synchronization are completed and verified, as already requested. Keep all infrastructure free.

Create a short docs/IMPLEMENTATION-CHECKPOINT.md containing completed work, changed data contracts, verification, known limitations, and the next task. Finish the functional slice before generating the full art/audio collection or expanding to every region. Do not repeat the research or introduce a new framework.
```

For subsequent work, use:

```text
Continue PROS from docs/IMPLEMENTATION-CHECKPOINT.md. Implement the next incomplete phase of docs/EXPERIENCE-OVERHAUL-PLAN.md. Preserve the established contracts and previous working flows. Complete the phase, run checks appropriate to the changed behavior, and update the checkpoint. Do not replace implementation with another roadmap.
```

The plan makes no fixed claim about credits, time to completion, or current production readiness. Small phases and a compact checkpoint reduce repeated context and make unfinished work explicit.
